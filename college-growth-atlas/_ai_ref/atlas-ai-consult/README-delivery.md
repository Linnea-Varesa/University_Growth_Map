# AI 咨询模块 · 对接说明

> 给队友看的文档。看完你应该能在 **30 分钟内**把它挂到「大学成长地图」上，不用改动你现有的任何逻辑。

---

## 0. 一句话说明

这是一个**独立模块**：右下角一个悬浮按钮 + 侧边面板。它不接管你的页面、不修改你的 DOM、不改你的数据。
它做的唯一一件事是：**读你存在浏览器里的那份数据，压成摘要，带着摘要去问大模型**，给出针对这个学生的建议。

技术形态：单文件、零依赖、纯前端、无后端、无外部请求（除了阿里云的模型接口）。
所有 CSS 类名都有 `atlas-ai-` 前缀，不会和你的样式打架。

## 2. 合并步骤

### 步骤 1（必须）：引入并挂载

在入口 HTML 的 `</body>` 前加两行：

```html
<script src="./atlas-ai-consult.js"></script>
<script>AtlasAI.mount();</script>
```

如果主站是 **Vite / React / Vue** 构建的项目：

```js
// main.js 或 App 的 useEffect 里
import './atlas-ai-consult.js';   // 副作用引入，会在 window 上挂 AtlasAI
AtlasAI.mount();
```

到此为止它就能用了——模块会自动扫描 `localStorage`，挑出最像主数据集的那份对象。
**但这一步是「猜」的，请继续做步骤 2。**

### 步骤 2（强烈建议）：把数据直接给它

自动扫描可能挑错（尤其你 `localStorage` 里有多份数据时）。最可靠的是主动喂：

```js
// 放在主站数据加载完成之后，任意位置
window.AtlasAIProvider = () => ({
  profile:        state.profile,          // 档案
  experiences:    state.experiences,      // 经历（含能力标签）
  directions:     state.directions,       // 方向（含意向程度）
  experiments:    state.experiments,      // 方向体验卡（含进度）
  opportunities:  state.opportunities,    // 机会库（含报名截止）
  majors:         state.majors,           // 专业探索
});
```

变量名按你实际的来，只要把对象交出去就行。**字段名不用改**——模块是通用压缩，不认字段名，
但**字段越清楚，AI 的回答越准**（下面第 3 节有建议）。

> 这个函数会在用户**每次打开面板时**被调用，所以拿到的一定是实时数据。

### 步骤 3（建议）：给各板块加「问 AI」入口

这是体验差距最大的一步。用户不该自己复述一遍背景，点一下就应该得到针对性回答：

```html
<!-- 方向卡片上的按钮 -->
<button onclick="AtlasAI.open(`帮我评价这个方向：${d.name}（意向 ${d.intent}/5，已有能力：${d.have.join('、')}）`)">
  问 AI
</button>
```

```html
<!-- 经历条目上的按钮 -->
<button onclick="AtlasAI.open(`帮我把这段经历写成简历上的能力证据：${e.name}，我担任 ${e.role}`)">问 AI</button>
```

```html
<!-- 机会详情上的按钮 -->
<button onclick="AtlasAI.open(`这个还值不值得报：${o.name}，${o.deadline} 截止`)">问 AI</button>
```

`AtlasAI.open(text)` 会打开面板并预填这句话，用户确认后发送（也可以直接回车）。

### 步骤 4（必须）：加一句隐私说明

这条不能省，理由见第 6 节。建议放在面板入口附近或「数据与备份」弹窗里：

> 「AI 咨询会把你的经历摘要发送给阿里云模型，仅用于生成建议。原始数据不上传。」

## 3. 数据契约（字段建议）

模块不需要你改任何字段名，但**下面这些字段存在时，AI 的回答质量会明显不同**：

| 实体 | 关键字段 | 为什么重要 |
|---|---|---|
| 经历 `experiences` | `name` 名称、`role` 角色、`tags` 能力标签、`status` 状态、`detail` 职责与成果 | 「经历提炼」卡要靠这个把记录变成简历证据 |
| 方向 `directions` | `name`、`intent` 意向程度、`required` 需要的能力、`have` 已有基础 | 「方向排序」「能力缺口」两张卡全靠它对比 |
| 体验卡 `experiments` | `name`、`direction` 所属方向、`status`、`progress` 进度 | 「本周聚焦」要判断「有没有在推进」 |
| 机会 `opportunities` | `name`、`type`、`deadline` 报名截止、`status` | 「机会取舍」要算剩余天数、排优先级 |
| 专业 `majors` | `name`、`content` 学习内容、`careers` 相关职业、`level` 了解程度 | 「专业探索」卡 |
| 档案 `profile` | `grade` 年级、`major` 专业 | 决定建议的尺度（大二和大四该做的事完全不同） |

如果这些字段在嵌套对象里（比如 `state.data.experiences`），没关系——只要整体对象交出去就行，
压缩逻辑会递归进去。**唯一要保证的是：这些数组不要超过几千项**（正常个人数据不可能超）。

## 6. 为什么必须做隐私声明（这条最重要）

主站现在的卖点之一是「数据只保存在当前浏览器」。**AI 会打破它**——数据要发给阿里云模型才能生成回答。
如果不说清楚，一旦用户发现，坏掉的是整个产品的信任，不是这一个功能。

模块里已经做了三件事来兜住：

1. **发送前可验证**：面板底部有「看清楚要发什么」，展开就是将要发出的 JSON 原文。
   用户能亲眼确认发出去的是摘要，不是他的完整备份。
2. **只发摘要**：自动剔掉 `id` / 时间戳 / `base64` / `data:` 开头的内容，字符串截断到 120 字，
   整体压到 6000 字符以内。作品链接、完整备份不会整包发出去。
3. **无后端**：Key 存 `localStorage`，请求由浏览器直连百炼。

**没有我们的服务器，也就没有任何第三方能留存用户数据。** 这句话是能对用户讲的。

## 9. 技术备忘（出问题先看这里）

| 现象 | 原因 / 处理 |
|---|---|
| 面板打不开 | 检查 `AtlasAI.mount()` 是否在 DOM 之后执行；`window.AtlasAI` 是否存在 |
| 显示「没找到你的数据」 | `localStorage` 里没有可解析的 JSON，或者用 `AtlasAI.setProvider()` 指定 |
| 提示「Key 无效」 | 模块会把 4 个地域逐个试一遍并列出结果；**全是 401 才是 Key 真的无效** |
| 提示「被限流」 | 429 说明鉴权是通的，只是请求太快，等十几秒 |
| 回答很空泛 | 数据没喂进去。看验收清单第 3、5 条 |

**已处理的坑**（这些是调试踩出来的，不用再踩一次）：

- **地域隔离**：同一个 Key 只在一个地域有效，用错地方返回 401。模块自动逐个试，通了的就用。
- **429 不等于 Key 无效**：限流说明鉴权成功，不能当失败处理。
- **不预判 Key 格式**：百炼的 Key 长度和字符集由它自己决定（实测有 110+ 字符、含 `.` 的），
  模块只拦「放不进 HTTP 头」的字符。
- **模型名回退**：`qwen-turbo → qwen-plus → qwen-max`，避免百炼调整模型名时把好 Key 判死。
